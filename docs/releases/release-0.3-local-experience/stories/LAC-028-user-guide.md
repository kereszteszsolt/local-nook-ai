# LAC-028: User guide

## Status

Implemented

## User story

As a LocalNook user, I want one accurate guide for setup, daily use, privacy, and troubleshooting so that I can use implemented capabilities without confusing them with planned work.

## Context

At the start of this story, engineering documents described individual boundaries, but public guidance was fragmented and some repository presentation still described obsolete in-memory behavior.

## Scope

Create `docs/user-guide.md` from verified behavior and link it to startup, screenshot, architecture, privacy, troubleshooting, and release evidence.

## Acceptance criteria

- [x] Document supported prerequisites and both existing-host and containerized Ollama startup modes.
- [x] Explain model installation, discovery, eligibility, and selection.
- [x] Explain chat submission, streaming, stop, regenerate, new chat, copy, and thinking-mode behavior.
- [x] Explain conversation reopening, per-conversation model/thinking state, deletion, reload behavior, and any recoverable storage errors.
- [x] Explain system-prompt management, the protected built-in prompt, folders, activation, import, export, restore, and deletion behavior.
- [x] Describe supported Markdown, highlighted code, Mermaid, KaTeX, and bounded Vega-Lite output accurately.
- [x] Describe actual browser-local storage, origin boundaries, Ollama request context, privacy limits, and explicit deletion paths.
- [x] Include troubleshooting for Ollama availability, missing models, browser-origin errors, endpoint overrides, Docker, WSL, browser tests, and rich rendering.
- [x] Link to the screenshot gallery, architecture, storage/context, Ollama integration, testing, and Releases 0.1 through 0.3.
- [x] Verify every documented capability and command against the current application and avoid presenting planned behavior as implemented.

## Verification

- Reviewed every guide section against current UI, facade, repository, context-builder, Ollama adapter, renderer, package, Compose, and prior release evidence. A final independent read-only review found no remaining accuracy blocker.
- Base and two-file overlay `docker compose config --quiet` validation passed. The guide separates foreground Compose startup from the second-terminal model-pull command and preserves the documented browser-reachable endpoints and volume-deletion warning.
- Every relative documentation link resolved, including the testing anchor. The nested Markdown fences were balanced and the extracted Vega-Lite example parsed as JSON.
- `npm ci` passed in `mcr.microsoft.com/playwright:v1.62.1-noble`. The production build passed at 4.71 MB, above the 4.5 MB warning threshold and below the 5 MB error threshold.
- The full ChromeHeadless suite reached 93/94. The sole failure is the unchanged `SystemPromptRepository` current-localStorage migration test; LAC-028 changes documentation only.
- The screenshot workflow passed 5/5 and regenerated byte-identical hashes for all five approved PNGs. Its real browser renderer successfully produced the exact Mermaid and bounded Vega-Lite examples used by the guide.
- A standalone Node Mermaid parse attempt was not a valid browser-renderer substitute because Mermaid's DOMPurify integration requires a browser DOM. It failed before diagram validation; the real browser-rendered screenshot assertion is the applicable evidence.
- Host WSL still has no usable Linux Node binary, so build and browser verification used the matching Docker image. No new live-Ollama or Ollama-CLI smoke was run; current startup wording was checked against LAC-025/LAC-026 evidence and unchanged runtime configuration.

## Out of scope

Developer API documentation, unsupported platform guarantees, hosted Ollama instructions, and documentation for future authentication, cloud sync, RAG, or telemetry are excluded.

## Implementation evidence

- `docs/user-guide.md` now provides one current user path for native and container startup, model selection, chat controls, conversation and prompt lifecycle, rich rendering, privacy boundaries, deletion, troubleshooting, screenshots, and release references.
- The guide distinguishes browser-local storage from configured Ollama processing, exact-origin isolation from encryption, New chat from deletion, completed output from non-durable failed persistence, and confirmed conversation deletion from immediate custom-prompt deletion.
- Linked engineering indexes and current-state sections no longer describe implemented conversation persistence as planned. Release 0.2 is reconciled as sixteen implemented stories while retaining each story's historical verification evidence and limitations.
- The root README remains unchanged because LAC-030 owns its release-presentation rebuild.
